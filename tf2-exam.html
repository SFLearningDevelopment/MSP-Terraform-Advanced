You start with a flat configuration that keeps its state on your computer. Your job is to make it ready for a team: move its state to S3 with locking, reorganise it into a module without replacing anything, and adopt a bucket that was created by hand. Use the module labs for reference.

Starting configuration

Create a folder tf2-graded-lab with this file, run terraform init and terraform apply, and check it works before you change anything.

tf2-graded-lab/main.tf

terraform {
  required_version = ">= 1.12.0"
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 6.0" }
  }
}

provider "aws" {
  region = "us-east-1"
}

resource "aws_vpc" "main" {
  cidr_block = "10.30.0.0/16"
  tags       = { Name = "tf2-graded-vpc", Project = "tf-course-2" }
}

resource "aws_subnet" "public" {
  vpc_id     = aws_vpc.main.id
  cidr_block = "10.30.1.0/24"
  tags       = { Name = "tf2-graded-public", Project = "tf-course-2" }
}

resource "aws_security_group" "web" {
  name_prefix = "tf2-graded-web-"
  vpc_id      = aws_vpc.main.id
  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
  tags = { Project = "tf-course-2" }
}

output "vpc_id" {
  value = aws_vpc.main.id
}

Requirements

  1. Remote state. Store state in an S3 bucket you create with the AWS CLI (versioning on), using the s3 backend with encrypt = true and use_lockfile = true. Move the existing state into it with terraform init -migrate-state.
  2. Module. Move the VPC, subnet and security group into a local module at ./modules/network, with input variables for the VPC CIDR, the subnet CIDR and a name prefix, and outputs for the VPC id, subnet id and security group id. Call it from the root module as module "network".
  3. No replacement. Add moved blocks so the three resources move to their new addresses (for example module.network.aws_vpc.main) without being destroyed or created.
  4. Root output. The root vpc_id output reads the value from the module.
  5. Import. Create one S3 bucket manually with the AWS CLI. Adopt it with an import block and a matching aws_s3_bucket resource block in the root module.

Run it

terraform init -migrate-state   # after adding the backend block
terraform fmt -recursive
terraform validate
terraform plan -out=tfplan      # copy this output into box 1
terraform apply tfplan          # copy this output into box 2

Box 1 should show each resource has moved to its module address and end with Plan: 1 to import, 0 to add, 0 to change, 0 to destroy. Box 2 should end with Apply complete! Resources: 1 imported, 0 added, 0 changed, 0 destroyed. Any add, change or destroy means something does not match yet.

After you submit, clean up: add force_destroy = true to the imported bucket and apply, run terraform destroy, then empty and delete the state bucket.

Before you paste

Remove anything secret from the output. Terraform does not print your AWS keys, but check for passwords or tokens you may have added yourself.
