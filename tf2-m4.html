Before you begin

Every folder of .tf files is a module. The folder you run Terraform in is the root module. A child module is another module that the root module calls with a module block. Modules let a team write a VPC or web server once and use it in many places.

1

Where modules come from

Local paths, the Terraform Registry, Git and other sources.

The source argument of a module block says where to find the module. Terraform downloads non-local modules into .terraform/modules when you run terraform init (or terraform get).

Source typeExample
Local path"./modules/web" or "../shared/network" (must start with ./ or ../)
Public Terraform Registry"terraform-aws-modules/vpc/aws" (namespace/name/provider)
Private registry (HCP Terraform)"app.terraform.io/my-org/vpc/aws"
GitHub"github.com/my-org/terraform-aws-web"
Any Git server"git::https://git.example.com/web.git?ref=v1.2.0"
S3 bucket or HTTP URL"s3::https://s3.amazonaws.com/bucket/web.zip"
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 6.0"

  name = "tf-course"
  cidr = "10.0.0.0/16"
  azs  = ["us-east-1a", "us-east-1b"]
  public_subnets = ["10.0.1.0/24", "10.0.2.0/24"]
}
Exam tip

Local modules are not downloaded or cached; Terraform reads them in place. Registry modules show their inputs, outputs and examples on their Registry page, and verified modules are reviewed by HashiCorp.

2

Inputs, outputs and variable scope

What a module can see, and how values pass between modules.

A module is sealed off from its caller. It cannot read the caller's variables, locals or resources, and the caller cannot read the module's resources directly. Values cross the boundary in two ways only:

  • In, through arguments in the module block, which set the child module's input variables.
  • Out, through the child module's output blocks, read as module.<name>.<output>.

modules/web/main.tf (child module)

variable "vpc_id" {
  type = string
}

variable "instance_type" {
  type    = string
  default = "t3.micro"
}

resource "aws_security_group" "web" {
  name_prefix = "web-"
  vpc_id      = var.vpc_id        # only sees its own variables
}

output "security_group_id" {
  value = aws_security_group.web.id
}

main.tf (root module)

module "web" {
  source        = "./modules/web"
  vpc_id        = aws_vpc.main.id      # root value passed in
  instance_type = "t3.small"
}

output "web_sg" {
  value = module.web.security_group_id  # child output read out
}
  • A child module variable without a default must be set in the module block, or init/plan fails.
  • A child module cannot be given values with -var or .tfvars; those set the root module's variables only.
  • Modules can take count, for_each, depends_on and providers, like resources.
  • In state, a module's resources have addresses such as module.web.aws_security_group.web.
3

Module versions and good structure

Pin versions, and organise a module the standard way.

The version argument uses the same constraint syntax as providers (~>, >=, =).

  • version works only for modules from a registry (public or private). It is not allowed for local paths.
  • For Git sources, pin a tag or commit in the URL instead: ?ref=v1.2.0.
  • The dependency lock file does not record module versions. Pin them in the module block.
  • To move to a newer allowed version, run terraform init -upgrade.

Standard module structure

modules/web/
  main.tf         # resources
  variables.tf    # inputs, with descriptions and types
  outputs.tf      # outputs
  versions.tf     # required_providers (no provider blocks)
  README.md       # what it does and how to call it
Watch out

Child modules should declare required_providers but should not contain provider blocks. The root module configures providers, and child modules inherit them, or receive them through the providers argument.

4

Lab: registry module and your own module

Build the network from the public VPC module and the server from a local module.

Create this folder structure:

tf2-lab-m4/
  main.tf
  modules/
    web/
      main.tf
      variables.tf
      outputs.tf

tf2-lab-m4/modules/web/variables.tf

variable "vpc_id" {
  type        = string
  description = "VPC to place the server in"
}

variable "subnet_id" {
  type        = string
  description = "Public subnet for the server"
}

variable "name" {
  type        = string
  description = "Name prefix for resources"
}

variable "instance_type" {
  type    = string
  default = "t3.micro"
}

tf2-lab-m4/modules/web/main.tf

terraform {
  required_providers {
    aws = { source = "hashicorp/aws", version = ">= 5.0" }
  }
}

data "aws_ami" "al2023" {
  most_recent = true
  owners      = ["amazon"]
  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }
}

resource "aws_security_group" "web" {
  name_prefix = "${var.name}-web-"
  vpc_id      = var.vpc_id
  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_instance" "web" {
  ami                         = data.aws_ami.al2023.id
  instance_type               = var.instance_type
  subnet_id                   = var.subnet_id
  vpc_security_group_ids      = [aws_security_group.web.id]
  associate_public_ip_address = true
  user_data                   = <<-EOF
    #!/bin/bash
    dnf install -y httpd
    echo "Hello from the ${var.name} module" > /var/www/html/index.html
    systemctl enable --now httpd
  EOF
  tags = { Name = "${var.name}-web" }
}

tf2-lab-m4/modules/web/outputs.tf

output "public_ip" {
  value = aws_instance.web.public_ip
}

output "security_group_id" {
  value = aws_security_group.web.id
}

tf2-lab-m4/main.tf

terraform {
  required_version = ">= 1.12.0"
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 6.0" }
  }
}

provider "aws" {
  region = "us-east-1"
  default_tags { tags = { Project = "tf-course-2", Lab = "m4" } }
}

module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 6.0"

  name           = "tf2-m4"
  cidr           = "10.20.0.0/16"
  azs            = ["us-east-1a", "us-east-1b"]
  public_subnets = ["10.20.1.0/24", "10.20.2.0/24"]
}

module "web" {
  source    = "./modules/web"
  name      = "tf2-m4"
  vpc_id    = module.vpc.vpc_id
  subnet_id = module.vpc.public_subnets[0]
}

output "web_url" {
  value = "http://${module.web.public_ip}"
}
cd tf2-lab-m4
terraform init          # downloads the VPC module into .terraform/modules
ls .terraform/modules   # vpc is there; web is not, because it is local
terraform plan
terraform apply
terraform state list    # see the module.vpc... and module.web... addresses
terraform destroy

If init reports that no version of the VPC module matches ~> 6.0, check the latest version on its Registry page and use that major version.

Module recap. Modules come from local paths, registries, Git and other sources, and init downloads the non-local ones. Values go in through module arguments and come out through outputs; a module cannot see its caller. Pin registry modules with version, and Git modules with ?ref=.
